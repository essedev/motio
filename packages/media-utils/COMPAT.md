## Measured behaviour

- `getAudioData` decodes with the browser's `decodeAudioData` at the requested rate (48000 by default). Results are cached by `src` and sample rate; omitting `sampleRate` shares the entry with 48000. `isRemote` is true for anything that does not start with the page origin except `data:` URLs, so relative paths and `blob:` URLs count as remote, as in Remotion. Failed loads are not cached.
- `visualizeAudio` takes `2 * numberOfSamples` samples of the first channel starting at `floor(t * sampleRate) - numberOfSamples` (clamped at 0, zero-padded past the end), converts them to 16-bit values (`x * 32768` for negative samples, `x * 32767` otherwise, rounded to 32-bit float, then truncated and wrapped), divides by the channel's peak on the same scale (cached per `resultId`, as Remotion does, so data reusing a `resultId` reuses its peak), and returns the FFT magnitudes divided by `numberOfSamples`, smoothed across bands by one 3-tap average pass followed by two in-place passes (first and last band kept). With `smoothing` the result is the mean of frames `f - 1`, `f` and `f + 1`. `optimizeFor` is accepted; Remotion's two FFTs agree to rounding, so Motio uses one.
- `getWaveformPortion` bars are the mean absolute value of `floor((floor(end * sr) - floor(start * sr)) / numberOfSamples)` samples each; samples outside the data count as zero; with `minus-one-to-one` every other bar, starting with the first, is negated. No bar fits: `[]`.

## Approximated: `useWindowedAudioData`

Window selection, `resultId` (`<src>-windows-<indices>`), `dataOffsetInSeconds`, sample rate (the file's own), duration, channel count and errors match Remotion for WAV files. The samples differ slightly:

- Remotion's windows overlap: each window boundary repeats one sample (sometimes the window starts one sample early), so its data is 1 to 3 samples longer than the file span and later samples are shifted by up to 3. Motio's windows tile the file exactly. Measured on the grid: `visualizeAudio` (16 bands) differs by at most 0.042 absolute, `visualizeAudioWaveform` (8 values, 0.1 s window) by at most 0.0028; the test asserts both below 0.05.
- WAV files are read with HTTP Range requests (8, 16, 24 and 32-bit PCM, 32 and 64-bit float). Other formats are decoded whole once at 48 kHz with `decodeAudioData` and sliced, so long compressed files are held in memory, and their duration is the decoder's (an MP3 with encoder padding reads 3 s where Remotion's demuxer reports 3.00098 s, which can change the last window). Remotion decodes them window by window with Mediabunny.
