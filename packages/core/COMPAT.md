# Compatibility with Remotion

How the pure functions of `@motiojs/core`, what `Interactive` renders and what `AnimatedImage` shows compare with the published `remotion` package. Every row is checked by the co-located tests against fixtures recorded from Remotion's public API by `tools/oracle` (`pnpm install && pnpm record` there) and `tools/oracle-render` (`pnpm record:animated-image`), never from its source code.

Recorded version: **remotion 4.0.545** (stamped in every fixture under `src/__oracle__/`).

Error is relative for values with magnitude at least 1 and absolute below.

## Behaviour identified black-box

These are the places where the docs alone did not determine the numbers; each was found by testing hypotheses against the recordings.

- `random`: a number seed is multiplied by 1e10 and a string seed is hashed with the Java-style hash (h = 31 h + c over UTF-16 code units); the result is the state of one mulberry32 step, divided by 2^32. `NaN` and infinite seeds give 0.
- `Easing`: `bezier`, `ease`, `circle` and `bounce` clamp t to [0, 1]; the other curves extrapolate their formula.
- `spring`: for a damping ratio of 1 or more, the critically damped response is used (as if the ratio were exactly 1), not the overdamped solution. With `durationInFrames`, frames past the duration return exactly `to`. Frames before the start hold the value at time 0.
- `Easing.spring`: for 0 < t < 1 it is `spring({ frame: t * 30, fps: 30, durationInFrames: 30, durationRestThreshold })`; t <= 0 gives 0 and t >= 1 gives 1. With a truthy `allowTail`, t >= 1 gives `spring({ frame: t * d, fps: 30 })` with d the natural duration (`measureSpring()` at the threshold). The function's `remotionShouldExtendRight` is the `allowTail` value (default `false`). The configuration is validated on the first evaluation that needs the spring, not when the easing is created.
- `measureSpring`: the first frame within the threshold that stays within it for the next 18 frames. `overshootClamping` is ignored. A `NaN` position (mass <= 0, negative stiffness) counts as settled.
- `interpolateColors`: colors are quantised to 8-bit RGBA before interpolating (alpha included, so `0.3` reads back as `0.302`), channels are interpolated with `clamp` whatever the options say, and the output rounds channels and gives alpha to 3 decimals. `lab()` and `lch()` use the D65 white (0.95047, 1, 1.08883) with no Bradford adaptation and the 7-digit XYZ to sRGB matrix; out-of-gamut colors are clipped per channel.

- `interpolate`, which outputs are CSS values: a string is parsed as one when every space-separated token is a number followed only by letters or `%` (`1e2px` is not), when a token is a `transform-origin` keyword (`left`, `center`, ..., any case), when it is `x`/`y`/`z` and an angle, or always with `outputType: "transform-origin"`. Other strings are discrete: allowed only if every keyframe is a string, and only with `easing: Easing.step1` (the function itself, or an array of it); a number next to one throws `UnsupportedStringInterpolationValueError` (a `TypeError`). Numbers next to CSS strings are scale values, and the output is then a string.
- `interpolate`, CSS values: the kind follows the units (none: scale; lowercase CSS lengths and `%`: translate; `deg`, `rad`, `grad`, `turn`: rotate); every keyframe must have the same kind (a transform-origin counts as translate) and each axis the same unit across the whole range. The number of components is the maximum over the range; a missing component is the kind's default: for scale, y copies x and z is 1; for translate and rotate, 0; for transform-origin, only a value written with keywords or under `outputType: "transform-origin"` gets y = 50%, others keep the translate default. `transform-origin` keywords become percentages (`top left` and `left top` alike; a vertical keyword before a length means `<length> <keyword>`); a third component must be a length. Results are rounded with `Math.round(n * 1e6) / 1e6` and written without trailing zeros (never `-0`).
- `interpolate`, rotations with an axis: once any keyframe has an axis (`x 90deg` or `1 0 0 90deg`), every keyframe becomes `ax ay az angle`; a multi-angle value then throws. A non-zero angle without an axis turns about z. A zero angle without an axis takes an axis by its role in the segment: at the start, the first explicit axis after it; at the end, the first explicit axis before it, looking past non-zero angles but stopping at another zero angle; otherwise z. The axis components are interpolated like the angle.
- `interpolate`, output modes and extrapolation: `perceptual-scale` maps each component (of numbers, tuples, CSS values and font weights) to `sign(v) v^2` and back, except that equal keyframes return their value untouched. `identity` fills every component with the input (`"-1px -1px"`, `"-1 -1 -1 -1deg"`); for discrete strings and booleans it throws only when the input reaches that side. A single keyframe returns its value normalised (`"left"` gives `"0% 50%"`) and needs no `Easing.step1`.
- `interpolate`, easings that extend right (`remotionShouldExtendRight === true`, as `Easing.spring({ allowTail: true })` sets): every earlier segment with such an easing adds `value(p) - end value`, with p computed from the unclamped input and the value after `perceptual-scale`; an active segment with such an easing is not clamped on the right.
- `interpolate`, font weights (`outputType: "font-weight"`): numbers and numeric strings from 1 to 1000, `normal` (400) and `bold` (700) in any case, no surrounding spaces; the result is a number, not rounded.

- `Interactive`: an element renders itself, with every prop except the timing ones, like a `<Sequence layout="none">` around it; its children see the shifted timeline. Crops become `clip-path: inset(...)` with unrounded percentages, overlapping opposite crops both 50%, rounded with the border radius. Premounted and postmounted elements get `opacity: 0; pointer-events: none`, then `styleWhilePremounted`/`styleWhilePostmounted`. `withSchema()` without `wrapInSequence` passes every prop through plus `controls: null`; with it, and with `create()`, the component receives its own props, `style` (with the crop) and `ref`. `create({ layout: "absolute-fill" })` renders a full-size container with `overflow: hidden` that takes `style` and the crop.

- `AnimatedImage`: the canvas bitmap is `width` by `height`, each falling back on its own to the image's intrinsic size (`width={120}` on a 64x64 image gives 120x64), and the canvas gets no CSS size; `style` is passed through as is, `width` and `height` in it included, and so are other attributes (`className`, `id`). Unknown `loopBehavior` and `fit` values do not throw. An invalid `playbackRate` throws a `TypeError` naming the prop, as `<Sequence>` does. Remotion shows the frame whose start is nearest to the current time (a tie going to the later frame), and a play that stops is over only after its end; Motio's rule is below.

## Deliberate differences

- `Easing.spring` with `stiffness: 0` or `durationRestThreshold: 0` throws on first use. Remotion never returns (and later `Easing.spring` calls in the same page fail with `RangeError: Too many properties to enumerate`).
- `measureSpring` (and `spring` with `durationInFrames` or `reverse`) with `stiffness: 0` and a threshold below 1 throws `Spring stiffness must be greater than 0, ...`. Remotion never returns in that case.
- `AnimatedImage` timing (D-066): Motio shows the frame whose display interval contains the current time, from the sum of the previous durations (inclusive) to the next start (exclusive). Remotion's nearest-start rule shows each frame up to half of the previous frame's duration early: over the 684 recorded frames of the 14 cases with regular delays, 410 are identical and 274 are one image frame apart: in 271 Motio still shows the previous frame, up to 100 ms after Remotion moved on (the fixture's 200 ms frame followed by an 80 ms one); in 1 Motio clears a `clear-after-finish` play at its exact end (frame 24 at 30 fps, 800 ms) where Remotion still shows the last frame; in 2 (`playbackRate` 2 at 2.4 s and 4 s, exact ends of a loop) Remotion shows the last frame and Motio the first.
- `AnimatedImage` frames with a duration of 0 last 100 ms, as browsers show them. On `short-delays.gif` (delays of 0, 10, 20 and 100 ms) Remotion stays on the first frame for all 21 recorded frames at 60 fps (333 ms); Motio shows the frames for 100, 10, 20 and 100 ms, so 9 of the 21 differ.
- `AnimatedImage` without `onError`: a file that cannot be loaded or decoded fails the render with an error naming the file, as `<Gif>` does; Remotion leaves an empty canvas and reports nothing. With `onError`, Motio passes an `Error` naming the file, with the browser's error as its `cause`; Remotion passes the browser's `DOMException` itself. An HTTP error is reported as such (`HTTP 404 Not Found`), where Remotion reports that the decoder does not support `text/plain`.
- `AnimatedImage` finds the format from the file's first bytes (GIF, PNG, WebP, AVIF, JPEG), and uses the response's content type only for other files, so an image served as `application/octet-stream` still plays. Not recorded for Remotion.

## Not implemented yet

Parts of the 4.0.545 API outside the current scope:

- `Interactive`: the Studio's editing (selection, dragging, controls). Schemas are exported as data and ignored.
- `AnimatedImage`: `effects` (a non-empty list throws) and `effectsOutputSize` (ignored), which need `@remotion/effects` (D-066 dropped it).

- `interpolateColors`: none of the documented formats is missing; `color()` and space-separated `rgb()`/`hsl()` are rejected, as in Remotion.
